# Lua: migration to tree-sitter-grammars/tree-sitter-lua v0.5.0

## Context

| | Before | After |
|---|---|---|
| Grammar | [Azganoth/tree-sitter-lua](https://github.com/Azganoth/tree-sitter-lua) @ `a943944` (2020, Lua 5.3-ish, unmaintained) | [tree-sitter-grammars/tree-sitter-lua](https://github.com/tree-sitter-grammars/tree-sitter-lua) `v0.5.0` (2026-02, Lua 5.1-5.5 + LuaJIT literals) |
| Where | git submodule `languages/lua/tree-sitter/semgrep-lua` (generated in an external repo, `opengrep/ocaml-tree-sitter-semgrep`) | the same submodule path, now pointing to [jetbrains-qodana/opengrep-lua-new](https://github.com/jetbrains-qodana/opengrep-lua-new), self-contained: grammar sources + regeneration script + generated code (first developed as the folder `semgrep-lua-new` of this repository) |
| Parser tables | generated by tree-sitter 0.20.6, ABI 13 | generated by tree-sitter 0.22.6 (the runtime version opengrep links), ABI 14 |
| External scanner | `scanner.cc` (C++) | `scanner.c` (C) |
| CST -> AST_generic | `languages/lua/generic/Parse_lua_tree_sitter.ml` written for the old CST | rewritten for the new CST |

Latest Lua release at the time of writing: 5.5.1.

The upstream v0.5.0 grammar can't be loaded by tree-sitter 0.22.6 as is (it is
an ES module). It *can* be generated by 0.22.6 once converted to CommonJS, and
the output (ABI 14) works with the 0.22.6 runtime. So no runtime upgrade is
needed, and the other ~35 tree-sitter languages are not affected.

## Plan

Each item is one commit, except item 11 (several commits).
Items 1-21 follow the numbering of the initial gap analysis.

| # | Item | Notes |
|---|---|---|
| 0 | Tooling: `opengrep test` understands Lua `--` comments in `ruleid:`/`ok:` annotations | Needed to run the Lua rule tests |
| 1 | Vendor the upstream grammar `tree-sitter-lua` v0.5.0 into `semgrep-lua/fyi/semgrep-grammars/src/tree-sitter-lua` | Pinned commit and license kept |
| 2 | ESM -> CommonJS prep step | `export default grammar(...)` becomes `module.exports = grammar(...)`, so tree-sitter 0.22.6 can load it |
| 3 | Regeneration script with tree-sitter CLI 0.22.6 (ABI 14) | `semgrep-lua/scripts/regenerate.sh` |
| 4 | C external scanner, dune library without `-lstdc++` | |
| 5 | OCaml CST bindings generated with `ocaml-tree-sitter` (opengrep fork of `ocaml-tree-sitter-core`, multicore-friendly bindings); first version of the generated library | Library is temporarily named `tree-sitter-lang.lua_new` so it can coexist with the old submodule |
| 6 | semgrep extension: `...` as a statement | The new grammar has no expression statements |
| 7 | semgrep extension: `__SEMGREP_EXPRESSION` entry point for expression patterns | Same approach as Rust/C#/Kotlin |
| 8 | semgrep extension: `...` anywhere in a parameter list | `function f(..., $X)` |
| 9 | semgrep extension: deep ellipsis `<... e ...>` | New |
| 10 | semgrep extension: metavariables, incl. `$...ARGS` | `identifier` is the word token, so it must remain a single token |
| 11 | Rewrite of the CST -> AST_generic converter (several commits: skeleton, expressions, statements, loops, functions, tables, patterns) | `languages/lua/generic_new`, library `parser_lua.ast_generic_new`. Not linked into any executable until item 22 |
| 12 | Lua 5.4 attributes `<const>` / `<close>` (and the 5.5 prefix form `local <const> a, b`) | `<const>` -> `KeywordAttr Const`, others -> `OtherAttribute` |
| 13 | Lua 5.5 `global` declarations: `global x [= v]`, `global function f`, `global [<attr>] *` | without value -> `UseOuterDecl` (like Python's `global`), with value -> `VarDef` with a `global` attribute, function -> `FuncDef` with a `global` attribute, `global *` -> `OtherDirective` |
| 14 | Lua 5.5 named vararg parameter `...args` | `ParamRest` with a name |
| 15 | Contextual keyword `global` used as a name | plain identifier |
| 16 | Strings: structured content, escape sequences, long brackets | value is the source text between the delimiters, as before |
| 17 | Numbers: integers vs floats, binary literals, LuaJIT suffixes, imaginary | `Int` / `Float` / `Imag` (before: always `Float`) |
| 18 | `self`, `next`, `_G`, `_VERSION` are plain identifiers now | `self` was first kept as `IdSpecial Self`, then made a plain name (port of `d8454b5` from main) |
| 19 | Function names `a.b.c:m`, implicit `self` of methods | |
| 20 | Shebang line | ignored |
| 21 | Comments | ignored (extras) |
| 22 | Switch opengrep to the new parser: final library names, remove the old submodule and converter | |
| 23 | Tests: whole opengrep test suite + migration rules pass; useful migration cases added to `tests/parsing/lua`, `tests/patterns/lua`, `tests/rules` | Several commits |
| 24 | Corpus validation on the 30 projects, results in `corpus-results.md` | |

Two extra fixes came out of the validation (separate commits):

* the rule prefilter required the implicit `self` of `function T:m()`
  patterns in the target (`src/rule/Pattern.ml`, affected the old parser too);
* upstream, `"--[[x"` started a block comment inside a short string; short
  strings are single tokens in the semgrep extension.
